# 10 · MCP 与工具权限设计

AI 酋长 Andy · 微信 AIPMAndy · [个人官网](https://metaver.vip/) · [星觉科技](https://www.a6no1.cn/)

MCP 是连接模型与外部能力的协议，不是授权本身。必须在工具服务端实施身份、最小权限、输入校验和操作审计。读取与写入分开。

**案例：**客服工具只允许 read_policy；提交退款的工具不在试点范围。

## 动手操作

- 先阅读官方 MCP 入门课程（来源 D），理解 tools、resources、prompts。
- 把 lab.fde.retrieve 当作只读工具实现，设计 read_policy(question) 的 JSON 输入与证据输出。
- 用 templates/tool-contract.md 写出身份来源、允许角色、拒绝条件及审计字段；测试匿名角色和经理角色。**交付物：**只读工具契约 + 权限测试

**验收：**客户端请求不能自行声明生产身份；无权限不返回内容；写操作另建审批。

**失败处理：**本地 CLI 的 --role 只是模拟身份，不能用于生产身份认证；真实系统必须服务端验证。

**可复制 Prompt**为只读知识检索工具定义 JSON schema、授权规则、超时与审计事件，禁止提供可执行任意命令的接口。
