接手陌生仓库应先定位业务入口、测试、依赖和部署契约。先读后写，建立基线，限定变更面，采用最小补丁。AI 生成代码不代表可合并。

**案例：**模拟客户要新增售后政策检索。把本仓库当作客户仓库，先读 README 与测试，不重构整个项目。

## 动手操作

- 克隆仓库或解压项目包，用 git init 建立本地基线（已是仓库则跳过）。
- 使用你已有的代码助手，先让它列出调用链、风险与改动计划；人工确认。
- 新增一条测试与对应实现，运行 python -m unittest discover -s tests -v，检查 diff。**交付物：**变更计划 + 可 review 的补丁 + 测试日志

**验收：**无无关依赖或文件删除；不新增真实凭据；每项变更有可复现证据。

**失败处理：**助手试图自动部署时停止，回到本地分支；只允许经过评审的发布。

**可复制 Prompt**先只读分析 README、lab 和 tests。列入口、依赖、风险与最小测试方案，未经确认不要改无关文件。
